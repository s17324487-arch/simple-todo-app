## 道と配置

- 幹線は車道4＋両側の歩道2、生活道路は車道2＋両側の歩道2、路地は2マス。店は東西道路の北側に置き、南のドアから2マスの入口を予約する。
- TOWN-01 の中心線・幅によるベクター描画を使用。交差点は隅切り、中央線は交差点で切る。今回の4町の車道は直交するため、階段状の斜道を作らない。今後斜道を足す際もタイル境界ではなく連続したベクター縁を使う。
- 街灯・街路樹は歩道の車道側に4マスおきで交互配置。もう一方の1マスと店の入口は空ける。店先の品物は建物の用途別リスト、道路沿いは道具類、広場は噴水・彫刻というまとまりにする。
- 港の桟橋の両側は水面。通れる中央を予約し、待合所の前で人とすれ違える。滑走路には09/27・末端標識・中心線・縁灯があり、曲がる誘導路が駐機場につながる。一般の歩行ルートには数えない。

## 保存データと機能

`Save.KEY` と SCHEMA 1 を維持。町・全既存建物・お店・ミニゲーム（link / relay）・乗り場・NPC・季節対象・宝箱のIDと機能を保持。取得済み宝箱、季節の記録、所持品、おかねは変換しない。外からのワープは同じ行き先の新しい入口へ接続する。

古い保存座標が建物・水面・立入制限区域や孤立区画になった場合、公共の歩ける範囲から最も近いマスへ移す。座標が使える場合はそのまま。ドア・ワープ・NPCの初期位置は救済先から除き、入場直後の移動や重なりを避ける。家の出口は座標の直書きではなく家の建物から求める。

## 検証と絵

- `npm run check` に `tools/town-check.mjs` を含む。旧ID・機能・全旧通行位置の救済・入口の判定・道路・密度・専用素材数・同一SVGの改名だけになっていないことを検査する。
- `npm run audit:town -- --check town city harbor airport`：木・柵・背景を小物数から除外。歩ける場所の半径2マスの空白（NPCは物体として数えない）、建物の型の比率、道の連結を計測する。小さいスマホ相当の11×19マスを各通行地点へ置き、建物（灯台・管制塔を含む）・小物・人の3つが画面に入るか確認する。
- `npm test`、`npm run test:full`：古い位置と987654コインを持つセーブを再開し、持ち物・家具・部屋・店の進行・イベント記録を比較。3人で移動できること、NPCを避けた入口への経路、実際の買い物/交通の入口、再保存・FPSを確認する。
- `node tools/town-screenshots.mjs`：全体図の前後比較、各町3地点×390×844・375×667、計測値を `docs/screenshots/towns/` へ保存。素材は `tools/preview.html` に一覧を追加。
- 新規SVGのコードは `js/town-renewal-art.js`、街区は `js/town-renewal.js`。平和台の見本SVG・配置ファイルは変更しない。
