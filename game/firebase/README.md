# オンライン（E5）の Firebase の設定（オーナー向け）

ゲームのオンライン機能（すまほの「みんな」: おてつだいのスコアのランキング・ほかの人のおうち・ぷりくら／コンビニの「みんなの くじ」: いちばんくじをみんなで同じロットで引く）は、Google の Firebase の **無料プラン（Spark）** で動く。
`game/js/online-config.js` が空のあいだは、ゲームの中では「じゅんびちゅう」と出て、どこにもつながらない。
2026-10-06 に、オーナーが作ったプロジェクト（`nerikas5858`・データベースはシンガポール）の値を入れた。手順 4 のルールを貼ると使えるようになる（ロックモードのままだと「よめなかったよ」と出る）。

> **2026-10-06（UI-100・みんなの くじ）でルールが増えた。** 手順 4 をもう一度やる（`database.rules.json` を全部貼りなおして「公開」）。貼りなおすまでは「みんなの くじ」だけが「よめなかったよ」になる（ほかの機能と「みせた データを けす」はそのまま動く。くじのデータは前のルールでは誰も書けないので、消すときもくじの分は足さない）。

## 1. やること（Firebase のコンソール）

1. https://console.firebase.google.com/ で **新しいプロジェクト** を作る（例: `pokapoka-town`）。
   - リポジトリ直下の ToDo アプリのプロジェクトとは **分ける**。匿名ログインを有効にすると、ToDo 側のルールが「ログインしていれば読める」だった場合に ToDo のデータが見えてしまうため。
   - Google アナリティクスは不要（オフでよい）。
2. 「構築 → Authentication → 始める → ログイン方法」で **匿名** を有効にする。
3. 「構築 → Realtime Database → データベースを作成」。
   - 場所は **シンガポール（asia-southeast1）** がおすすめ（日本からいちばん近い）。
   - 「ロックモードで開始」を選ぶ。
4. Realtime Database の「ルール」タブに、このフォルダの `database.rules.json` の中身を **そのまま全部** 貼りつけて「公開」。
5. 「プロジェクトの設定（歯車）→ 全般 → マイアプリ → ウェブ（`</>`）」でアプリを登録する（Firebase Hosting は不要）。
   表示される `firebaseConfig` のうち、次の 3 つを Claude に伝える（`js/online-config.js` に入れる）:
   - `apiKey`（`AIza…`）
   - `databaseURL`（`https://<名前>-default-rtdb.asia-southeast1.firebasedatabase.app`）
   - `projectId`
   - ウェブ用の API キーは秘密の値ではない（プロジェクトを指す名前。データはルールで守る）。

## 2. 無料プランの範囲（2026-10 時点）

| 項目 | 上限 | このゲームでの使い方 |
| --- | --- | --- |
| 同時接続 | 100 | すまほの「みんな」か「みんなの くじ」のボードを開いているあいだだけ 1 本（閉じると切る） |
| 保存 | 1 GB | 1 人あたり 名前 1 件 ＋ ボードごとのスコア 1 件 ＋ 見せたおへや 1 件 ＋ 見せたぷりくら 8 枚まで（1 枚 8 KB まで）＝ 100 KB くらい。いちばんくじは 1 ロット（80 枚）で 6 KB くらい（引くほど増える。1000 ロットで 6 MB） |
| ダウンロード | 10 GB／月 | 開いたボードのスコアだけ読む・おへやは 1 件ずつ・ぷりくらは「ぷりくら」タブを開いたときに新しい 24 枚（200 KB まで）・いちばんくじは「みんなの くじ」のボードを開いているあいだ いまのロットだけ（6 KB まで＋増えたぶん） |
| 匿名ログイン | 1 つの IP から 1 時間に 100 件まで作成 | 1 台に 1 つ（ログインの記録は端末に残る） |

- 上限をこえると、その月はデータベースが止まる（**請求は来ない**。Spark はクレジットカードを登録しない）。
- 出典: [Firebase の料金](https://firebase.google.com/pricing)・[Realtime Database の制限](https://firebase.google.com/docs/database/usage/limits)

## 3. 送るもの・送らないもの（オーナーの許可 2026-10-05）

- 送る: 匿名の ID（自動）・決まった言葉から選ぶ名前（例「ふわふわ ねこ」＝ コード `2-2`）・おてつだいのスコア（おみせの Lv・あそびかた・サーバーの時刻）。
  - おへやの家具の並び: 「この おへやを みせる」を押したときだけ（壁紙・床・広さ・家具の種類と場所・向き・フィギュア台のフィギュア）。「みせるのを やめる」で消える。
  - 見せると決めたぷりくら（ゲームの絵のデータ）: 「しゃしん」アプリで「みんなに みせる」を押したものだけ（8 枚まで）。背景・ブース・3 人の並び・ポーズ・表情・服・ペンの線・スタンプ・キラキラ・決まった言葉の番号（自由な文字は送れない）。撮った日時は送らない。「みせるのを やめる」・写真を消す・「みせた データを けす」で消える。
  - ほうこく（いやな絵・いたずら）: だれがどの写真を報告したか（`reportlog`）は、ゲームからはだれも読めない（オーナーはコンソールで見られる）。数（`reportcount`）だけ読める。3 人以上が報告した写真は、ゲームの一覧に出なくなる。
  - いちばんくじの結果（オーナーの指示 2026-10-06「一番くじについて、他のユーザーのくじ引き結果を連携するようにして。」）: コンビニのくじのボードで「みんなの くじ」を選んで引いたときだけ。お店・ロット・何枚目・匿名の ID・引いた時刻（サーバーが入れる）・D〜F賞で選んだ種類の番号。名前は送らない（`players` の名前を読んで表示する）。「みせた データを けす」で、自分の引いたくじの ID を消す（くじの箱の中身は変えられないので、引いたことだけが「だれか」として残る）。
- 送らない: 本名・メール・位置・カメラの写真・自由に打つ文字。コイン（ゲームの中のお金）は端末の中だけで計算する（サーバーには送らない）。
- 18 歳以上の同意ボタンを押した人だけがつながる。オンにするたびに同意を聞く。
- プレイヤーは ≡ の「せってい」で、いつでも「オンラインを とめる」「みせた データを けす」（サーバーの名前とスコア・匿名アカウントを消す）ができる。

## 4. データの形（`database.rules.json`）

```
v1/players/{uid}        = { n: "2-2", t: サーバーの時刻 }
v1/scores/{ボード}/{uid} = { s: スコア, n: "2-2", t: サーバーの時刻, l?: おみせの Lv, m?: "easy" | "normal" | "hard" }
v1/roomlist/{uid}       = { n: "2-2", t: サーバーの時刻, c: 家具の数, k: おへや（main など） }
v1/rooms/{uid}          = { n, t, k, w: 壁紙, f: 床, z: "s" | "e"（広さ）, i: [{ a: 家具, x, y, r?: 向き, s?: "l"（左の壁）, g?: フィギュア }]（80 こまで） }
v1/photos/{uid}_{写真の番号} = { n, t, b: 背景, k: ブース, z: 0 | 1（アップ）, r: "wanko,gachan,goji"（並び）, c: "ポーズ.表情" ×3, o: "色:場所=服;…" ×3,
                            m?: 動かした場所, p?: ペンの線, s?: スタンプ, x?: 言葉の番号.x.y.色.傾き, e?: キラキラ }（ぜんぶ ASCII の文字列）
v1/reportcount/{写真のキー} = 報告の数（だれでも読める）
v1/reportlog/{写真のキー}/{uid} = "bad" | "spam"（だれも読めない）
v1/kuji/{お店}/cur            = いまのロットの番号（ないときは 1。お店は lawson | sevenbun）
v1/kuji/{お店}/lots/l{ロット} = { n: 引いた枚数（80 まで）, pc?: 選んだ回数, d: { k{何枚目}: { u: uid, t: サーバーの時刻, p?: D〜F賞で選んだ種類（0〜2）, o?: 選んだ順 } } }
v1/kujime/{uid}/{お店}_l{ロット} = true（自分が引いたロット。「けす」で自分のくじを探す。自分しか読めない）
```

- 読めるのはログインした人（スコアはボードごと・おへやは 1 件ずつ・おへやの一覧とぷりくらはまとめて・報告は数だけ）。書けるのは自分の uid のところだけ（ぷりくらはキーが「自分の uid ＋ _ ＋ 写真ごとのランダムな番号」。撮った時刻はキーにも入れない）。形・範囲・ほかの項目がないことをルールで確かめる。
- 報告は 1 人 1 回だけ・数は報告の記録といっしょに 1 だけ増える（取り消すと 1 減る）・自分の写真とない写真は報告できない、をルールで確かめる。
- いちばんくじ: 書けるのは「いまのロットの、引いた枚数と同じ番号のくじ（`k{n}`）を、自分の uid とサーバーの時刻で 1 枚」だけ。枚数は同じ書き込みで 1 だけ増える（80 まで）ので、2 人が同じくじを引くことはない（同時なら片方が失敗して引き直す）。引いたくじは消せない・時刻も変えられない（自分の uid を "" にするのだけできる）。D〜F賞の種類は自分のくじに 1 回だけ（選んだ順の番号は 1 ずつ）。売り切れたロット（80 枚）は、だれでも次のロットへ進められる。
  - どの賞が出たかはサーバーには書かない。みんなのゲームが「お店・ロット・何枚目・サーバーの時刻」から同じ計算で決める（時刻はサーバーが入れるので、引く人は賞を選べない）。
- ルールを新しくしたとき（PR が増えたとき）は、手順 4 をもう一度やる（`database.rules.json` を全部貼りなおす）。
- 開発者むけ: ルールを変えたら `node tools/rules-emulator.mjs <firebase-database-emulator の jar>` で、本物の Firebase のエミュレーターとテスト用のにせのサーバー（`tests/online-fake.mjs`）が同じ答えを返すか確かめる（Java が要る・`npm run check` には入れていない）。
- ボードの id はゲームが決める（`Online.boards()`。例: `crepe`・`burger_mac`・`brain_spot`・`kobo_numpla_expert`・`korokoro_score`）。

## 5. 困ったとき

- 「よめなかったよ（つなぎさきの きまりを たしかめてね）」と出る → ルールを貼り忘れている（ロックモードのまま）。手順 4 をやりなおす。
- 「いまは つながらないよ」 → 匿名ログインが無効、または apiKey・databaseURL がちがう。手順 2・5 を確かめる。
- 全部のデータを消したい → Realtime Database の「データ」タブで `v1` を削除する。
- いちばんくじの古いロットを消したい → 「データ」タブの `v1/kuji/{お店}/lots` から、`cur` より小さいロット（`l1` など）を削除してよい（いまのロットと、その 1 つ前は残す。選んでいない D〜F 賞がある人のため）。
- よくないぷりくらを消したい → 「データ」タブの `v1/photos` からその写真（キー）を削除する。だれが報告したかは `v1/reportlog/{写真のキー}` で見られる。報告の数を戻すときは `v1/reportcount/{写真のキー}` と `v1/reportlog/{写真のキー}` をいっしょに削除する。
